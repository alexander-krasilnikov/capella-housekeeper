## Why

The README still opens by declaring this project "phase one: read-only visibility" with "cleanup/governance actions (pause, delete, notify owners, staleness rules) intentionally out of scope" - all four of which have since shipped. Thirty changes have been archived since that text was written; 15 capabilities have specs and the README meaningfully covers three. Worse than the omissions are the contradictions: it documents a JSON file store that is now SQLite, a `data/settings.json` that no longer exists, a 7-day retention default that is now 30 (and load-bearing at 30), a Capella API key needing only "read access" when the app now deletes clusters, and an editable API base URL that the `dashboard-settings` spec explicitly requires be fixed. A new operator following it today gets wrong results, not just incomplete ones.

The largest single hole is that the Slack bot - which the README itself calls the app's "entire purpose" alongside sync - has no setup documentation at all. The required token types, the four required scopes, the Socket Mode model, and the non-obvious coupling where an empty app-level token silently suppresses sending exist only in TypeScript doc comments and archived design docs. So does the entire consent lifecycle, including `autoTurnOffOnInaction`, a setting that turns clusters off automatically when an owner ignores a request.

## What Changes

- Restructure the docs into a thin `README.md` (what this is, quickstart, pointers) plus a `docs/` directory, rather than growing the single README roughly threefold. The Slack setup walkthrough is a multi-step journey through an external dashboard, and the consent semantics deserve a page an operator can read *before* enabling a setting that deletes clusters.
- Add `docs/slack-setup.md`: creating the Slack app, the bot token (`chat:write`, `users:read.email`, `im:write`) and app-level token (`connections:write`), where each is pasted in Settings, the Socket Mode outbound-websocket model (and the reassurance that follows from it - no inbound endpoint, no request URL to register, nothing exposed to the internet), and the failure modes: empty bot token disables notifications entirely, empty app token *also* suppresses sending, and a cluster whose derived owner is absent or not email-shaped is skipped with no fallback recipient.
- Add `docs/consent-workflow.md`: the Recency tiers and the thresholds that produce them, notification firing on tier *transition* rather than every sync, the reminder/expiry/snooze lifecycle, what the reconciliation loop does after approval (including its pre-action re-verification), and a prominent treatment of `autoTurnOffOnInaction` and `maxSnoozes` as the two settings that cause destructive action without an explicit human yes.
- Add `docs/operations.md`: running as a persistent service, upgrading (`npx` a newer tag against the same data directory, migrations run automatically inside a single transaction that rolls back on failure - and the fact that this is *not* a backup, since the application never writes one, so taking one is a manual step the documentation must supply), what lives in the data directory, the retention floor of 30 days and why lowering it breaks consent lineage, session-secret rotation, and a troubleshooting section covering the known failure modes (Node below 22.13.0, a read-only Capella key, Slack `missing_scope`, an empty dashboard before the first cycle completes).
- Add `docs/development.md`: local setup, the test suite (`npm test`, `npm run typecheck`, `npm run test:coverage`), what CI gates on and that it runs against the declared minimum Node version, and how to cut a release (tag `v*`, `scripts/package-release.mjs`, artifact attached to the GitHub Release).
- Rewrite `README.md` to describe the product as it now exists - cross-org visibility *plus* owner-consent governance and manual lifecycle actions - and document a **read-only posture** as a supported, deliberate configuration (notifications off, no destructive per-tier settings) rather than as the project's current phase. This is the honest bridge from what the README claims today.
- Correct every factual error catalogued above, fill the `<org>/<repo>` placeholders left unresolved in all three install/service snippets, fix the broken link to the now-archived `cluster-monitoring-dashboard` change, remove the stale "Known open risk" section about the Activity Log endpoint (resolved in `capellaClient.ts` - it is org-scoped with a filter, not cluster-scoped), document that the Capella API key needs write access for turn-off/delete rather than read access, and replace the 8-file project layout with one that reflects the ~25 modules in `src/lib/` plus `bin/`, `scripts/`, and `.github/`.
- Not in scope: no application code changes, no new user-facing features, no CHANGELOG (a separate concern), and no attempt to document capabilities that do not yet exist.

## Capabilities

### New Capabilities
- `end-user-documentation`: the guarantees the documentation set itself must meet - that every credential the application requires is documented with its exact minimum scopes, that every command shown is runnable as written with no unresolved placeholders, that every setting capable of destructive action is documented as such before an operator can enable it, and that documented storage/configuration locations match where the application actually reads and writes. Sits alongside `automated-quality-gate` and `release-distribution` as a repo-level rather than product-level capability.

### Modified Capabilities
- None. No application behavior changes. The stale "four-tier recency" wording in `cluster-age-status`'s purpose line (the implementation returns three: `Fresh`/`Aging`/`Old`) and the residual "age-status" naming in `cluster-dashboard-ui` are corrections to non-normative prose, not requirement changes, so they are handled as tasks rather than delta specs.

## Impact

- **Docs**: `README.md` substantially rewritten and shortened; new `docs/slack-setup.md`, `docs/consent-workflow.md`, `docs/operations.md`, `docs/development.md`.
- **Specs**: new `openspec/specs/end-user-documentation/spec.md`; prose-only corrections to `openspec/specs/cluster-age-status/spec.md` and `openspec/specs/cluster-dashboard-ui/spec.md`.
- **Tests**: two new assertions in the existing Vitest suite guarding the drift classes this audit found in bulk - no documented command may contain an unresolved own-project placeholder, and numeric defaults quoted in documentation must match `DEFAULT_SETTINGS` (see design.md Decision 4). Test-only; no runtime behavior changes.
- **Code**: none. One adjacent inconsistency is worth noting but is deliberately left out of scope: `bin/capella-housekeeper.js` prints "change this in Settings" for the default login, which is now wrong - `proxy.ts` forces a redirect to `/change-password` instead. That is a one-line code fix, not a docs fix, and belongs in its own change.
- **Dependencies**: none.
- **No breaking changes**: documentation only.
